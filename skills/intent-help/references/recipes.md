# Prompts worth copying

Swap in the real feature, paths and ticket numbers. Informal wording works.

## Understand what to build

- `/grill-with-docs i want <feature>. grill me until nothing is assumed.`
- `/grill-with-docs users keep asking for <request>. find the job behind it before we design anything.`
- `/grill-me <plan, decision or piece of writing>` when there is no repo.
- `/need-first review this spec. which features have not earned their place?`
- `/domain-modeling we use "<word>" for two different things. settle it and update the glossary.`
- `/research how does <library or API> handle <thing>? primary sources only.`
- `/prototype i can't tell if this state model is right. build me something to click through.`

## Write it down

- `/to-spec` after the interview, in the same chat.
- `/to-tickets` after the spec, in the same chat.
- `/to-tickets <issue number or URL>` to split an existing spec.
- `/to-questionnaire i need answers from <person> about <topic> before i can decide.`

## Build

- `/implement <ticket number>` in a fresh chat, one ticket at a time.
- `/implement-spec <spec issue number>` to work the whole ticket graph in parallel.

## Big or unclear work

- `/grill-with-docs i want <product>` first, when the whole thing fits one sitting, however new it is.
- `/wayfinder <loose idea>` to chart the map, when it does not.
- `/wayfinder <map issue number>` to resolve the next decision.

## Design

- `/systems-design do we need a queue for <capability>? here is the load and what must not be lost: <facts>.`
- `/improve-codebase-architecture` when you have a spare moment.
- `/codebase-design design the interface for <module> a few different ways and compare them.`

## Incoming work

- `/triage` to sort new issues into agent-ready work.

## Housekeeping

- `/handoff the next session will <do what>.`
- `/wait-what` when a message did not make sense.
- `/wizard walk me through setting up <service>.`
- `/setup-intent` once per project.
